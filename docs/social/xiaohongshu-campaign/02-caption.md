# 让 AI 改大项目，我只看这 5 类证据

我现在验收 Coding Agent，不会先看最后那段总结。

跨文件、长时间、多个 Agent 一起做的任务，我按顺序看这 5 类证据：

1. Plan：目标、约束、验证方式有没有拆清楚。
2. Ownership：并行任务有没有明确的写入所有者。
3. Tool Output：命令是真的执行了，还是总结里只说「已经运行」。
4. Files & Diff：真正改了哪些文件，有没有越界。
5. Recovery：中断之后，对话、Agent 树、工具调用和模型状态能不能继续。

这不代表所有小改动都要走重流程。修一句文案当然没必要；但任务越长、改动越广、并行越多，缺少证据的风险就越高。

我把这套检查做进了 Threadlight：Plan → Agent → Tool → Diff → Recovery，放在同一条任务线上。项目已开源，官网和仓库里都有完整架构与自部署方式。

先收藏，下次让 AI 改大项目时照着过一遍。你会给这张清单补第 6 条什么？
